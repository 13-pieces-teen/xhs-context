## 0.4.0 检索与 Agent 循环

Skill 明确三方职责：Agent 拆解主题、必要条件与偏好，CLI 返回本地原文证据，Agent 回读后决定是否继续搜索。实际代码提供重复 `--query`、`--require`、默认正文筛选与显式 `--content all`；排序拆开实质内容与标签，等价查询不重复加分，摘录围绕命中并保留原文偏移。read 在 `schema_version=2` 中按笔记聚合，调用方读取 `blocks[]` / `assets[]`。数据库版本、原文与索引不需要迁移。

冻结库仍为 generation 1598。使用相同 12 个已知目标查询复测：默认返回页中的正文不可用候选均为 0；马德里变体覆盖 4/4 个已知目标，infra 变体覆盖 3/3。每个目标的排名和失败例均保留：`马德里 小吃`、`infra 入门` 及整句自然语言问题仍未返回目标；原先由 infra→容器扩词产生的误召回已去除。不能把本轮结果报告为整体准确率或所有查询均改善。冷启动 CLI 搜索的中位耗时约 634 ms，原基线约 609 ms；本轮未证明搜索提速。

同样 13 篇、185 个固定版本证据块（8,148 字符正文），JSON 从 92,510 降为 34,023 字符，减少 63.22%；每页 12,000 字符预算下分页从 9 次降为 4 次。逐块校验了 ID、版本、原文和位置一致性。这里没有模型 token 计量或全任务成本测量。

当前 Agent 实际执行马德里 4 次、infra 6 次离线 CLI 调用。马德里：按城市查询 → 回读不同城市段落 → 用新店名继续查 → 核对店名、原文地址及缺口。infra：找主题 → 回读资源介绍和简短路线 → 搜索 Sandbox / 推理优化 → 回读并发现隔离线索 → 进一步查权限 / 隔离 → 判断有限阅读候选。请求与响应见本机 `var/evaluation/20261120-search-v2/workflow/`，决策记录见 `agent-workflow.json`。

这是当前 Agent 已知案例的流程检查，查询决策由 Agent 在读到结果后作出，不是 CLI 的内置工作流。尚无独立盲测、人审标准答案、全库穷尽检索或外部教程查证。具体结果、残余问题和对照文件见本机[优化验证报告](../var/evaluation/20261120-search-v2/优化验证报告.md)。自动采集始终保持锁定。

## 数据与异常行为

Python 测试实际覆盖了以下行为：

- 中文短词、技术标识、少量别名和 Café/Cafe 检索；C++ 不退化为普通 C 查询。查询过程禁止网络连接，且不加载 OCR 模型。
- 相同内容与访问参数变化不重复生成版本；旧版本仍可追读。搜索代次变化后游标失效，固定版本阅读分页不受其他笔记更新影响。
- 整个 JSON 响应受字符预算限制；证据块不截断，正文字符位置可还原，缺失版本返回逐项错误。
- 重复批次 ACK、批次内容冲突、缺批禁止结束、预期总数不符、未知终点、两个完整扫描才确认移除。
- 中断任务恢复、单库 worker 文件锁、同一收藏视图不能并发开启两个扫描。
- 匿名访问被拒绝时暂停；正文、图片获取或 OCR 出现新的缺口时保留之前可检索的版本。
- 解析器保留 25 张图片清单、不执行页面脚本、不把作者简介或信息流摘要认作完整正文。
- 导出快照仅有每篇当前版本；备份恢复保留媒体和旧引用，校验对象哈希与路径边界。
- 本机 HTTP 的配对验证、浏览器 Origin 限制、批次提交，以及实际 CLI 的 UTF-8 标准输入、JSON 文件和退出码。
- Native Messaging 消息分帧、UTF-8、大小限制与不完整输入拒绝；实际原生入口自动初始化资料库并在 stdin 关闭后退出；浏览器请求 ID 的对应、断线后重连和失败批次不确认。
- CLI 和原生组件共用安装配置中的默认资料库；显式路径与环境变量仍可覆盖默认值。

扩展队列测试重新实例化存储访问对象模拟 service worker 生命周期，检查未确认请求仍保留；它不等同于操作系统级浏览器崩溃测试。

## 真实页面结构核对

另外通过浏览器只读 DOM 检查，核对用户已打开的 Edge 收藏页面；没有滚动、切换标签或启动归档。页面选中“收藏 → 笔记”，标签显示 969 篇，当前已加载 20 个不重复收藏卡片，均使用带访问参数的主页笔记链接。DOM 中另有 26 个已发布笔记卡片，所在区域为 `height: 0; overflow: hidden`，不能因子元素有尺寸就算入收藏。

这次观察用于修正当前收藏区域、主页笔记链接和 `subTab` 的识别规则。969 是页面显示的总数，20 是当时已加载卡片数；两者都不是成功归档数量。后续真实任务发现 851 条，但未完成全量列表验收。早期只读记录为 `var/validation/live-page-inspection.json`，不包含实际笔记标题、ID 或访问参数。

用户随后报告扩展停在“正在等待收藏列表加载”。复查发现真实页面给折叠区域设置 `height: 0; overflow: hidden; padding-top: 1px; box-sizing: border-box`，实际外框高度仍为 1 像素；旧逻辑将多个隐藏区域误判为可见，导致无法选定收藏列表。此前模拟页面缺少这条内边距，未能覆盖该问题。

扩展 0.2.2 改为同时检查扣除内边距后的内容尺寸。已先用补齐内边距的模拟页面复现 `loading / 0 cards`，再验证修复后为 `saved / 18 cards`；零尺寸、1 像素内边距、内边距加边框三种情形均通过。60 篇 Native Messaging 整批工作流也在该模拟页面上重新通过，结果含 `collapsed_panes_with_padding: PASS`。专项记录为 `var/validation/collapsed-pane-regression.json`。

已在用户现有 Edge 中重新加载扩展 0.2.2、刷新收藏页并打开扩展面板，实际看到“本机已就绪”“页面显示 969 篇笔记”及可点击的读取按钮，截图为 `var/validation/extension-live-ready.png`。这一步验证入口恢复，没有点击读取或启动全量归档。
